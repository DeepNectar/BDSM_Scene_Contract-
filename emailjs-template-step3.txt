EMAIL SETUP — FINAL VERSION (app v4.36 DH)

READ THIS FIRST — WHY THE CODE KEPT SHOWING IN THE BODY:
EmailJS's Gmail service ALWAYS HTML-escapes template
variables. Their {!!!} raw-HTML block does NOT work with
Gmail OAuth. So anything you send through
dashboard.emailjs.com appears as literal source code in
the email body — no app-side trick can beat that escaper.
That is why every previous fix still showed code.

THE REAL FIX (v4.36): 🚀 Send now defaults to
📧 FormSubmit.co, which renders raw HTML natively
(field _template = "raw_html"). No account, no API key,
no template to configure. The styled contract arrives as
a REAL HTML email in the body.

ONE-TIME SETUP (2 minutes)
--------------------------
1. Open the app -> ⚙ Email settings.
2. "Send via" = 📧 FormSubmit.co (already the default).
3. In the "Endpoint / key" field type the DESTINATION
   inbox address (any Gmail/Outlook/Yahoo address, e.g.
   honey@yourmail.com). Press Save.
4. Fill the form -> ✉ Email data -> type recipient in
   "Send TO" -> press 🚀 Send now.
5. FIRST send only: FormSubmit replies "Please confirm
   your email address". Open that inbox, click the
   confirmation link FormSubmit emailed (one tap).
6. Press 🚀 Send again -> the full styled contract lands
   directly in the email BODY. Every later send works
   instantly, no confirmation needed.

OTHER PROVIDERS (also selectable in ⚙)
--------------------------------------
* ✉ Formspree  — free form at formspree.io; paste the
  endpoint https://formspree.io/f/xxxxxxx or just id.
* 📨 Web3Forms — free access key from web3forms.com.
* 🟣 EmailJS   — still available, but its Gmail service
  escapes HTML, so the body will show markup unless the
  template uses the iframe-srcdoc copy the app sends for
  that provider. Not recommended anymore.

TROUBLESHOOTING
---------------
* Badge must say v4.36 DH — hard refresh (Ctrl+Shift+R)
  if it shows an older version (service-worker cache).
* 🧪 "Send render test" button in ⚙ settings proves the
  chosen provider renders HTML: BIG RED styled text = OK.
* Blank on phone? FormSubmit emails render best on
  desktop Gmail/Outlook; mobile clients may reflow.
